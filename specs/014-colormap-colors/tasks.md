# Tasks: Colormap Colors

**Input**: Design documents from `/specs/014-colormap-colors/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/colormap-api.md, quickstart.md

**Tests**: Included, following the plan: pytest for the colormaps, the frame writer and the API, and vitest for the new validation, texts and the rendered controls. Behavior in a real browser is checked by the quickstart steps.

**Organization**: Tasks are grouped by user story. Paths are relative to the repository root. Backend commands run in `backend/` with the venv's Python (`.venv/Scripts/python -m pytest`), frontend commands in `frontend/`. The API field is `colormap` (`summer`, `autumn`, `hot` or `cool`, default `hot`). This feature is mostly a **removal**: the harmonic hue rules, the per-frame energy brightness, the Saturation/Brightness roots and the three level steps are deleted, not hidden (research Decision 1).

**Findings while implementing (2026-10-11)**: matplotlib's `hot` starts at (10, 0, 0), not pure black; its `summer` and `autumn` 8-bit tables contain a few identical neighboring colors (253 and 232 distinct), so tests compare colors with `table[row]` and decode a color to its row only for `hot`; a silent file is not hidden by a threshold (no note is below a share of zero), so it keeps the first color. The spec and the plan documents were corrected to match.

**Working notes** (learned in features 010 to 013): do not use `git stash` to compare with old code (it emptied the index once; use the saved reference runs instead); keep each existing file's line endings (many files are CRLF) when editing from a script; write helper scripts to files with the Write tool rather than shell heredocs that contain backticks (the shell runs them as commands); do not run a bare `cat >` in a command (it waits for input and hangs). When a test file is rewritten, keep the intent of the tests that survive (smoothing, threshold, image types, writers) and delete only tests of code that is deleted.
