# Tasks: Interpolated Frames

> **Amendment 2026-10-13**: the interpolation function was removed after the user saw the rendered frames ("The others don't really work"). Only `blend` is made: there is no function dropdown, no `interpolate_function` field and no response key for it, and no `soft_light`, `hard_light`, `overlay`, `screen` or `subtract` code. A request that still sends `interpolate_function` is accepted and the field is ignored. [spec.md](spec.md), [data-model.md](data-model.md) and [contracts/interpolate-api.md](contracts/interpolate-api.md) describe the result; this document is kept as it was written, so the passages about the five other functions, option B and the function dropdown describe the first version.

**Input**: Design documents from `/specs/018-interpolated-frames/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/interpolate-api.md, quickstart.md

**Tests**: Included, following the plan: pytest for the checks, the numbering, the in-between frames, the writers and the API; vitest for the new validation, texts and the rendered controls. Behavior in a real browser is checked by the quickstart steps.

**Organization**: Tasks are grouped by user story. Paths are relative to the repository root. Backend commands run in `backend/` with the venv's Python (`.venv/Scripts/python -m pytest`), frontend commands in `frontend/` (run `npm` from PowerShell: the bash tool fails after it). The API fields are `interpolate` (whole number 1 to 5) and `interpolate_function` (`blend`, `soft_light`, `hard_light`, `overlay`, `screen`, `subtract`).

**Working notes** (learned in features 010 to 017): do not use `git stash`; keep each existing file's line endings (many files are CRLF, and `sed -i` can strip them) when editing from a script; write scripts with the Write tool and keep non-ASCII characters (such as `×`) out of bash commands and heredocs; no bare `cat >`; every test tone must sit on an analysis bin center; mutation-check the new tests (break the code, see them fail, restore); report honestly what was not verified (no real browser walk-through has ever been done in this project). The user wants to see what the result looks like, so the implementation ends with rendered frames sent to them (T017). If the baseline is red because of a change the user committed, keep their work and adapt the tests, and say so.

**Rules for the tests of this feature**: no test states a colormap name or a number of contour levels. Use `COLORMAPS`, `DEFAULT_COLORMAP`, `FIRST`, `SECOND`, `WITHOUT_BLACK`, `INVALID` from `backend/tests/colormap_names.py`. Pillow is the definition of the in-between frames (FR-006): the tests apply `Image.blend` and `ImageChops` themselves to the decoded drawn files and compare, and check blend again against a plain numpy weighted mix (within one level of 255). Helpers of `test_resolution_rendering.py` (`rgb`, `write`, `notes`) and the response-key and API helpers of `test_resolution_api.py` and `test_note_count_api.py` may be imported.
