# Tasks: Peak Tile Colors

**Input**: Design documents from `/specs/024-peak-tile-colors/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/beat-coloring.md, quickstart.md

**Tests**: Written first for each story (the project's practice): the position and the colors on plain arrays, `write_frames` at the pixel level, the API, and the page's group, controls, payload and summary (server-side rendering and source guards, since there is no browser or DOM library here). The look in the player is the manual step of the quickstart.

**Organization**: By user story: US1 the coloring itself (P1), US2 the checkbox, the two settings, the API and the page (P2), US3 the corners: no beat, hidden and silent tiles (P3). The library work for US3 is mostly inside US1's functions; its tests come after US2 because they go through the API too.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel (different files, no dependency on an unfinished task)
- Paths are from the repository root. The Spec Kit setup scripts cannot run here (PowerShell execution policy), so the feature files were written by hand. Backend checks run with the user's colormap lists possibly still inconsistent: use the temporary-default runner (`scratchpad/run_with_default.py`, file restored) and report the one expected list-mismatch failure. Edit files with their line endings preserved; avoid `sed -i`; scripts with backticks or non-ASCII go in files written with the Write tool; replace test functions only block by block and compare test counts before and after.
