# Tasks: Contour Image Type

**Input**: Design documents from `/specs/015-contour-image-type/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/image-type-api.md, quickstart.md

**Tests**: Included, following the plan: pytest for the contour drawing and the API, vitest for the list, the help text, the dropdown and the Blend width rule. Behavior in a real browser is checked by the quickstart steps.

**Organization**: Tasks are grouped by user story. Paths are relative to the repository root. Backend commands run in `backend/` with the venv's Python (`.venv/Scripts/python -m pytest`), frontend commands in `frontend/`. The API value is `image_type=contour`.

**Working notes** (learned in features 010 to 014): do not use `git stash` (it emptied the index once); keep each existing file's line endings (many files are CRLF) when editing from a script, and write scripts with the Write tool, never a bash heredoc containing backticks; no bare `cat >`; every test tone must sit on an analysis bin center; mutation-check the new tests (break the code, see them fail, restore); report honestly what was not verified (no real browser walk-through has ever been done in this project).

**Rules for the tests of this feature** (spec FR-004a and FR-014): no test states a number of contour levels or a colormap name. Use `COLORMAPS`, `DEFAULT_COLORMAP`, `FIRST`, `SECOND`, `DECODABLE`, `WITHOUT_BLACK`, `INVALID` from `backend/tests/colormap_names.py`; on the frontend derive the names from `COLORMAPS`. A band is only ever described as "within one band", tested as a tolerance on the position along the scale (research Decision 7).

## Phase 3: User Story 1 - A contour picture of the notes (Priority: P1) 🎯 MVP

**Goal**: With `image_type="contour"`, `write_frames` writes a 252 × 168 filled-contour picture per frame, drawn by matplotlib, on a fixed 0-to-peak scale of the selected colormap, with the levels chosen by matplotlib.

**Independent Test**: Make frames from a file in which one note sounds strongly in a stretch and all others are quiet, choose `contour` and the default colormap: a single bright region around the note's grid position, fading to the start of the colormap far from it, no axes or border; the same strength has the same color in other frames.

Use small hand-made `frames` arrays `(n, 88)` written with `write_frames(frames, tmp_path, colormap=name, image_type="contour")` and read the PNGs back with Pillow. Cover: (a) every file is exactly 252 × 168, opaque (alpha 255 everywhere), named `frame_000000.png` and up, one per input row, in a directory that is created; (b) no axes or border: the pixels along all four edges are not the figure background (compare the edge pixels with the picture's own colors: each edge pixel is within 1 per channel of the colormap's color at *some* position, found by sampling the colormap at 512 positions with matplotlib, and there is no pixel with alpha below 255); (c) orientation: a frame with one loud note at index 0 (top-left) and another file with one loud note at index 83 (bottom-right) have their brightest pixel regions in the top-left and the bottom-right quarter respectively, by comparing the position on the scale of the pixel colors found by nearest sampled colormap position, restricted to colormaps in `DECODABLE`, and for the others by simply comparing against the same picture mirrored (the picture of the note at 0 must differ from its vertical mirror); (d) the scale: for a frame with a loud note (value `peak`) and a note of half the value, the pixel at the loud note's grid point is within one band (tolerance 0.25 of the scale, see the rules above) of the colormap's far end, the half note's within 0.25 of the middle, and a grid point of value 0 within 0.25 of the start, expressed as "equal within 1 per channel to the colormap's color at some position within 0.25 of the expected position"; (f) hidden notes: with `threshold=T` the frame in which a note is below the threshold equals, file for file, the frame written for the same input with that note's value really set to 0 and the threshold 0; (g) smoothing and window are applied before drawing: a one-frame impulse with `smoothing` above 0 and window 3 gives a trace in the next frames that is absent with smoothing 0; (h) determinism: two runs are byte-identical; (l) `import app.services.frame_rendering` and `import app.main` do not import `matplotlib.pyplot` (check `"matplotlib.pyplot" not in sys.modules` in a subprocess) and a tiles job does not either.
